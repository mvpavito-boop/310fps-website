# Первый коммерческий выпуск

Объём: каталог, конфигуратор, заявка мастеру, оплата после согласования.
Разработка подготовлена для проверочной выкладки. Коммерческий выпуск ещё не принят.

## Реализовано

- Первый источник перехода (UTM, yclid, путь входа, домен реферера) сохраняется в текущей вкладке и передаётся с заявкой. Произвольные параметры URL не собираются.
- Отдельное обязательное согласие: сервер проверяет версию, сохраняет собственную отметку времени. Контекст записывается в JSON и текст заявки; уведомление сохраняет источник и факт согласия.
- `lead_submit` срабатывает после успешного ответа сервера. Просмотры SPA передаются через `hit`; Вебвизор отключён. Имя и контакт не передаются в параметры целей.
- Галерея конкретной сборки, выбор обложки 16:10 и кадров 4:3 из 12 моделей корпусов. 344 кадра в 17 сериях скопированы из готовой библиотеки с проверкой SHA-256; исходные ARW не изменены.
- Соответствие снимков сборке подтверждается отдельно в админке. Изменение состава или фотографий сбрасывает подтверждение. Снимки автоматически к товарам не привязаны.
- Числовые оценки FPS скрыты без протокола измерений. Формульный FPS конфигуратора снят с витрины. Пример паспорта подписан и не содержит вымышленных серийных номеров/просроченной гарантии.
- В карточке и конфигураторе указан расчёт после согласования вместо неподтверждённой рассрочки.
- Отдельные реквизиты оператора через окружение. Документы остаются проектами до заполнения реквизитов и подтверждения фактической схемы обработки данных. Production API не принимает заявки без полных реквизитов.
- Preview закрыт от индексации заголовком и robots.txt.

## Подключение базы

1. Подтвердить нужный проект и регион, восстановить доступ и сохранить резервную копию существующей базы.
2. Применить миграции `20260907154956_site_commerce_catalog.sql`, `20260907210000_site_content.sql`, `20260923203000_lead_context_and_saved_build_access.sql` последовательно. Старый `supabase_schema.sql` содержит DROP TABLE: его не использовать для обновления.
3. Заполнить переменные из `.env.example` отдельно для Preview и Production. Не коммитить значения секретов. В production требуется постоянное хранилище `CATALOG_STORAGE=supabase`.
4. `npm run catalog:migrate` — чтение и предварительный отчёт. Только после проверки удалённой версии: `npm run catalog:migrate -- --apply --expected-remote-revision N`. Скрипт сохраняет обе копии в `.local/migration-backups`, использует транзакцию с проверкой версии и проверяет запись чтением. Черновик не публикуется автоматически.
5. После заполнения цен, наличия и составов проверить каталог и опубликовать снимок через админку.

## Адрес и Telegram

Собственный домен не обязателен для проверки. `NEXT_PUBLIC_SITE_URL` должен содержать один проверенный адрес сайта. Webhook устанавливается только после готовности endpoint `/api/telegram`, с `secret_token`, совпадающим с `TELEGRAM_WEBHOOK_SECRET`. Текущий бот может обслуживать прежний сайт: до проверки новой выкладки его webhook не перенаправлять.

## Проверки и приёмка

```sh
npm test
npm run typecheck
npm run lint
npm run build
git diff --check
npm run release:check -- --online
npm run release:check -- --online --ads
```

Preflight только читает состояние. Код завершения 1 означает незакрытые условия; успешный preflight не заменяет живую приёмку.

- Цены одинаковы в каталоге, карточке и конфигураторе.
- Три тестовые заявки с пометкой «тест»: главная, товар, конфигуратор. Проверить запись, источник, согласие, уведомление и изменение статуса мастером.
- Перезапуск сайта сохраняет каталог и изменения админки.
- Проверить телефон, клавиатуру, reduced motion и сеть мобильного устройства.
- Создать счётчик Метрики, задать ID, настроить `lead_submit`, проверить достижение цели. Клики по телефону и Telegram — отдельные цели, не заявки.
- Подтвердить реквизиты, сроки, гарантию и фактические правила хранения/передачи данных. Затем ограниченный рекламный тест с согласованным бюджетом.

Документация Метрики: [SPA](https://yandex.ru/support/metrica/ru/code/counter-spa-setup), [цели](https://yandex.ru/support/metrica/ru/general/goal-js-event).

## Откат

Production не переключать до приёмки. Для кода использовать предыдущее готовое развёртывание Vercel; для данных — сохранённое состояние и history с проверкой текущей revision. Не откатывать таблицы командой DROP. При откате API учитывать обязательное поле согласия и миграцию context.
