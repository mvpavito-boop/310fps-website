# Variant B: фотоплан для premium custom lab визуала

Дата: 2026-05-05  
Проект: 310FPS Custom Lab  
Цель: заменить временную визуальную базу на реальные фотографии, которые поддерживают новый дизайн: крупные фото, больше воздуха, меньше карточек, editorial-подача и доверие к мастерской.

## 1. Краткий вывод

Сейчас сайт уже визуально готов под премиальную подачу, но почти все ключевые места используют один файл:

- `public/media/images/axiom.jpg`

Это нормальный временный placeholder, но для эффекта "custom lab" нужны реальные серии кадров: hero, пять LAB Series, карточки каталога, страницы товара, процесс сборки, паспорт ПК и детали качества.

Главный принцип: пользователь должен видеть не абстрактный игровой ПК, а реальную работу 310FPS: корпус, сборку, кабель-менеджмент, тесты, руки мастера, паспорт и готовый продукт.

## 3. Расширенный набор под весь сайт

### 3.1. Главная

| Файл | Кадр | Назначение |
| --- | --- | --- |
| `/media/images/editorial/home-hero-desktop.webp` | Готовый ПК крупно, видна глубина корпуса, чистый темный фон | Главный экран desktop |
| `/media/images/editorial/home-hero-mobile.webp` | Вертикальный кроп того же ПК, корпус крупнее | Главный экран mobile |
| `/media/images/editorial/lab-desk-wide.webp` | ПК на столе мастера, рядом инструменты или паспорт | SEO/доверие/о компании |
| `/media/images/editorial/passport-pc.webp` | Паспорт ПК + фрагмент корпуса | блок паспорта |
| `/media/images/editorial/stress-test.webp` | Экран с тестом + корпус в кадре | гарантия/проверка |

Требование: на hero не должно быть мелкого визуального шума. Фото должно читаться даже с темным overlay и текстовым блоком поверх.

### 3.2. LAB Series

Каждой серии нужен свой узнаваемый характер.

| Серия | Визуальный характер | Файл hero |
| --- | --- | --- |
| VECTOR | практичный, чистый, понятный, Full HD/FPS | `/media/images/lineup/vector-hero.webp` |
| SIGNAL | 2K-баланс, современный airflow, уверенная середина | `/media/images/lineup/signal-hero.webp` |
| CANVAS | эстетика, панорама, светлый/чистый корпус, аккуратный RGB | `/media/images/lineup/canvas-hero.webp` |
| SPECTRE | строгий темный high-end, минимум визуального шума | `/media/images/lineup/spectre-hero.webp` |
| AXIOM | флагман, максимальная мощность, дорогой корпус/контур | `/media/images/lineup/axiom-hero.webp` |

Для каждой серии желательно подготовить:

- `*-hero.webp` — основной кадр `4:3`.
- `*-detail.webp` — крупная деталь: GPU, СЖО, память, кабели.
- `*-mobile.webp` — вертикальный кроп `3:4`.

### 3.3. Каталог

Каталог сейчас содержит много моделей. Не обязательно сразу снимать каждую конфигурацию отдельно. Можно идти в 2 этапа.

Этап 1:

- один сильный общий кадр на каждую линейку: `vector`, `signal`, `canvas`, `spectre`, `axiom`;
- карточки внутри линейки используют общий кадр, пока нет отдельных фото.

Этап 2:

- отдельное фото для каждой коммерчески важной модели: `BASE`, `PRO`, `MAX`, `FLAGSHIP`;
- бюджетные/редкие модели могут использовать линейный fallback.

Рекомендуемая структура:

```text
public/media/images/catalog/
  vector/
    vector-lite-main.webp
    vector-base-main.webp
    vector-pro-main.webp
  signal/
    signal-base-main.webp
    signal-pro-main.webp
  canvas/
    canvas-base-main.webp
    canvas-pro-main.webp
  spectre/
    spectre-base-main.webp
    spectre-ultra-main.webp
  axiom/
    axiom-pro-main.webp
    axiom-flagship-main.webp
```

## 4. Товарная страница: обязательная галерея

Для каждой важной модели идеально иметь 6 кадров.

| Позиция | Кадр | Что доказывает |
| --- | --- | --- |
| 1 | Главный 3/4 ракурс корпуса | внешний вид и класс сборки |
| 2 | Внутренний план через стекло | аккуратность сборки |
| 3 | Кабель-менеджмент | инженерное качество |
| 4 | GPU / охлаждение / память крупно | ценность комплектующих |
| 5 | Паспорт ПК / тесты | прозрачность и гарантия |
| 6 | Сборочный процесс или выдача | реальность мастерской |

Когда эти фото появятся, следующий кодовый шаг:

- добавить gallery на `/catalog/[id]` и `/lineup/[id]`;
- использовать `gallery` из `LineupModel`;
- расширить `CatalogPC.images` до реальных кадров модели;
- оставить `getSafeImages` как fallback.

## 5. Стиль съемки

### Нужно

- Реальный ПК должен занимать 60-75% кадра.
- Фон темный, глубокий, но не полностью черный.
- Свет мягкий: видны стекло, кабели, видеокарта, вентиляторы.
- Цветовой акцент: оранжевый/красный 310FPS, но без перенасыщения.
- Кадры без случайных предметов, пыли, отражений фотографа и лишних коробок.
- Для белых корпусов сохранять чистоту белого, не уводить в грязно-серый.

### Не нужно

- Слишком темные фото, где ПК угадывается только силуэтом.
- Блюр ради "атмосферы".
- Стоковые абстракции вместо реального продукта.
- Сильный RGB-хаос, который спорит с оранжевым брендом.
- Мелкие фото корпуса издалека, где невозможно оценить сборку.

## 6. Кропы и экспорт

Для каждого ключевого кадра готовить минимум 3 версии.

| Версия | Размер | Где нужна |
| --- | --- | --- |
| Desktop hero | `2400x1500` или `2200x1400` | главная, серии |
| Product/card | `1600x1200` | карточки, товарные страницы |
| Mobile vertical | `1200x1600` | мобильные hero/product frame |
| OG | `1200x630` | соцсети, Open Graph |
| Thumb | `800x800` | каталог, related blocks |

Формат:

- Web: `.webp`, качество 78-86.
- Архив исходников: `.jpg` или `.raw` отдельно, не в `public`.
- Hero-файлы желательно держать до 350-500 KB.
- Thumb/card-файлы желательно держать до 120-220 KB.

## 9. Чеклист приемки фото

- Фото не темное: детали видны без выкручивания яркости.
- ПК занимает достаточно места в кадре.
- Есть свободная зона под текстовый overlay для hero.
- Фото не конфликтует с оранжевым градиентом сайта.
- На мобильном кропе не обрезается главная часть корпуса.
- Нет лишних наклеек, мусора, коробок, отражений.
- Серии отличаются визуально, а не выглядят как один и тот же кадр.
- Файлы названы по схеме и лежат в правильных папках.
- Есть web-версии и исходники отдельно.

## 10. Следующий кодовый шаг после фото

Когда появятся первые 12 фото:

1. Сложить web-версии в `public/media/images/editorial`, `lineup`, `catalog`.
2. Обновить `src/lib/data/lineup.ts`.
3. Обновить `baseImages` в `src/lib/data/catalog.ts`.
4. Добавить простую галерею на страницы `/catalog/[id]` и `/lineup/[id]`.
5. Проверить mobile/desktop screenshots.
6. Запустить `npm run lint` и `npm run build`.

## 11. Если фото будут позже

До съемки сайт можно вести с текущим `axiom.jpg`, но лучше не расширять визуальные блоки новыми placeholder-картинками. Дизайн уже подготовлен под настоящие фото; следующий качественный скачок будет именно от замены визуального материала, а не от новых декоративных элементов.
